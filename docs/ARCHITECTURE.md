# 云五笔架构

## v0.5.36 架构原则（固化）：云端优先，前端薄

**核心原则：能改后端就不改前端，避免用户频繁下载安装。**
1. **词库/联想/排序/热词全部云端化**：客户端只保留最小离线兜底（基础字库+词组+动态拼词）
2. **前端只负责交互与渲染**：键盘布局、候选展示、剪贴板、计算器面板
3. **变更分级**：
   | 变更类型 | 通道 | 用户影响 |
   |---|---|---|
   | 词库/热词/拼音/排序 | 云端 SCF 部署 | 无感（无需更新） |
   | 交互/布局/面板 | 客户端发版 | 需下载新 APK |
4. **云端能力清单**：五笔编码查询（2.6万字库）、动态构词、分类词 31 类 7659、拼音全拼/简拼、高频字排序、每日热词、英文翻译、连续联想
5. **默认策略**：新功能优先评估云端实现，云端不可行（需本地键盘交互）才走客户端

## v0.5.38 云端 hot 通道（落实"只改后端不改前端"）

**机制**：云端每次查询响应携带 `hot` 字段（本次编码高频单字，按《现代汉语常用字表》字频 top3）。
前端 parseCandidates 一次适配后，**高频字/词/热词的任何更新都只改云端，前端零发版**。

- 变更通道：词库/热词/高频字/排序 → 云端 SCF 部署（用户无感）
- 前端唯一适配点：parseCandidates 读 hot 字段（v0.5.38 一次性完成）
- 演进：云端可随时扩展 hot 为高频词（≥2 字）推送，前端无需再改

## v0.5.42 固化（2026-09-15，用户革命性要求）

### 1. 五笔词组必须按"全码规则"（非简码）
- 二字词 = 第1字全码前2码 + 第2字全码前2码
- 三字词 = 第1字全码首码 + 第2字全码首码 + 第3字全码前2码
- 四字及以上 = 前3字各首码 + 末字首码
- 例："不等于"=g(不gii首)+t(等tffu首)+gf(于gf前二)=**gtgf**（非 itgf——不=i 是简码，全码首笔=g）
- 云端/端侧反向索引均取"最长编码=全码"（_build_reverse_index 最长优先）

### 2. 云端规则实时生效（变更无需重新安装 App）
- 词频调整规则、中文词库（词组/单字）、英文翻译词库、排序/过滤规则**全部在云端**（SCF）
- 前端只负责：渲染 + 编码缓冲 + 上屏 + 云端结果回填
- 云瑞变更 → 部署 SCF → 用户下次查询即时生效（零安装包更新）
- 端侧只保留：字根字 + 一/二/三级简码 + 全码（wubi_single.txt）+ 891 条高频词组兜底（离线可用）

### 3. 前端最小化（安装包≤100KB）
- assets/wubi_phrase.txt 1757→891 条（22KB→10.4KB，字频和+强制高频词）
- 其余词组/热词/分类/翻译全部云端
